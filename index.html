3. How We Use Your Data

3.1 On-Device Data

  • Vault operation: Encrypting, storing, organizing, and displaying your photos and videos inside the vault.
  • Authentication: Verifying your PIN or biometric credential to unlock the vault. The app supports a Decoy Vault — a separate PIN that opens an empty vault, designed to protect you in coercion scenarios.
  • Calculator disguise: Running the fully functional calculator interface that disguises the app. The secret vault is accessed by entering your PIN followed by "=" on the calculator.
  • Intruder detection (optional): If you enable this feature, capturing and securely storing a front-camera photo when an incorrect PIN is entered, so you can identify unauthorized access attempts.
  • Secure deletion: When files are permanently deleted, they are overwritten 3 times (0x00, 0xFF, random data — DoD 5220.22-M standard) before being removed, making forensic recovery impractical.
  • Startup cleanup: On every app launch, any temporary decrypted files left from a previous session (e.g., after a crash) are securely overwritten and deleted before any UI appears.
  • Share-to-vault: You can share photos and videos directly from other apps into the vault using Android's Share Sheet. The app receives the shared file via intent, encrypts it, and deletes the intent reference.

3.2 AdMob Data

Data collected by AdMob is used solely by Google to display banner advertisements within the app. This supports the free version of the app. We do not receive, process, or profit from your individual AdMob data beyond the general ad revenue the app earns.

We do not use any collected data to build personal profiles, make automated decisions about you, or sell your information.

9. Security Architecture

Security is the core purpose of this app. We implement protections at every layer:

9.1 Encryption

  • AES-256-GCM: All vault files (photos, videos, thumbnails, intruder photos) are encrypted using AES-256-GCM with authenticated encryption before being written to disk. The encryption scheme used is AES256_GCM_HKDF_4KB via AndroidX Security-Crypto's EncryptedFile.
  • Android Keystore: The encryption master key is generated and stored in the Android Keystore System. Where hardware-backed security is available (Android 9+ with StrongBox), the key is stored in a dedicated hardware security module (HSM/StrongBox). Keys cannot be exported or extracted from the device.
  • Device-Bound Keys: Keys are tied to your specific device. Encrypted files copied from the device to another device cannot be decrypted.

9.2 PIN & Authentication Security

  • PBKDF2WithHmacSHA256: Your PIN is hashed using PBKDF2 with HMAC-SHA256, a 32-byte cryptographically random salt, and 100,000 iterations. Only the hash is stored — the plain PIN is cleared from memory immediately after hashing.
  • EncryptedSharedPreferences: PIN hashes, salts, and security flags are stored in EncryptedSharedPreferences (AES256-SIV key encryption, AES256-GCM value encryption), backed by Android Keystore.
  • Brute-Force Protection & Exponential Backoff: After 5 failed PIN attempts, the app enters a lockout. Subsequent lockout durations escalate: 30 seconds → 1 minute → 5 minutes → 15 minutes → 1 hour maximum.
  • Decoy Vault: You can configure a secondary "decoy" PIN. Entering this PIN opens an empty vault, allowing you to protect yourself in situations where you are coerced into revealing your PIN. The main vault remains hidden.
  • Biometric Authentication: Fingerprint and face unlock are supported. All biometric processing is handled entirely by the Android Biometric API — the app never accesses raw biometric data.

9.3 Storage & File Security

  • App-Private Storage: All vault files are stored in the app's private internal directory (files/vault/). Other apps on the device cannot access this directory, even without root access.
  • MediaStore Exclusion: A .nomedia file is created in the vault directory to prevent the Android MediaStore from indexing or thumbnailing vault contents. Vault files will never appear in the system gallery.
  • Secure Deletion (DoD 5220.22-M, 3-Pass): When a file is permanently deleted, it is overwritten three times — first with 0x00 bytes, then with 0xFF bytes, then with cryptographically random data — before the file entry is deleted. Each pass is synced to disk. This makes forensic recovery impractical.
  • Startup Temp-File Cleanup: Any temporary decrypted files left in cache/temp_media/ from a prior session (e.g., due to a crash or force-stop) are securely overwritten and deleted every time the app starts, before any content is displayed.
  • Backup Disabled: android:allowBackup="false" is set. Additionally, data_extraction_rules.xml explicitly excludes the vault, thumbnails, database, and all security preferences from Google Cloud Backup and Android device-to-device transfer.

9.4 Network Security

  • Vault contents have no network access path. The INTERNET permission is used exclusively by AdMob.
  • All AdMob network traffic uses HTTPS/TLS encrypted connections.
  • There is no cloud sync, no remote API, and no server-side component to this application.
User Responsibility: The security of your vault also depends on your device's overall security posture. We recommend: keeping your Android OS updated, using a strong device screen lock, not sharing your vault PIN with others, and regularly exporting important media to a secure backup. A forgotten PIN cannot be recovered — this is by design.

10. Your Rights & Controls

10.1 Direct In-App Controls

  • Access: View all vault contents at any time after authenticating with your PIN or biometric.
  • Organize: Create albums, add favorites, assign tags, rename files, and move files between albums.
  • Export: Export any photo or video from the vault back to your device gallery at any time.
  • Delete: Delete individual files, entire albums, or all vault contents. Items go to the recycle bin first; you can permanently delete them immediately or wait for automatic secure deletion after the retention period (default: 30 days).
  • Change PIN: Change your main vault PIN or decoy PIN at any time from Settings.
  • Disable Intruder Detection: You can disable the intruder detection feature in Settings. Existing intruder photos can be deleted from the Intruder Log screen.
  • Full Data Wipe: Clear all app data via Android Settings > Apps > Hide Calculator > Storage > Clear Data. This permanently removes all vault contents, the database, the PIN, and all preferences from your device.

10.2 Ad Personalization Opt-Out

To opt out of personalized advertising served by AdMob:

  1. Open Android Settings.
  2. Navigate to Google > Ads (path may vary by device manufacturer).
  3. Enable "Opt out of Ads Personalization" or tap "Reset advertising ID" to generate a new anonymous ID.

You will still see ads after opting out, but they will not be personalized based on your Advertising ID. This setting applies device-wide to all apps using AdMob.
